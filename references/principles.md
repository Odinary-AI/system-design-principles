# 原则与诊断参考

本表是跨领域工程启发式的综合，不是统一标准或完备定理。按任务读取相关编号。条目中的信号提示需要检查，并不直接证明设计有缺陷；证据例子也不是必须生成的文档。

## P01 目的适配与边界明确

- 判断：目标用户、核心任务、运行环境、成功标准与系统责任是否匹配。
- 信号：功能持续增加却无法解释收益；依赖外部服务完成任务却没有说明其条件。
- 证据：实际使用场景、验收要求、边界和依赖。通过演示不自动证明满足真实任务。

## P02 自洽性与必要完整性

- 判断：术语、单位、状态、规则、优先级和责任不矛盾；所选场景的必要路径完整。
- 信号：不同组件各自合法的行为组合后违反整体约束；异常时没有定义负责人或状态。
- 证据：状态转换、接口对照、端到端场景。完整性相对于任务边界，不要求穷尽世界上的所有情况；自洽也不等于符合现实。
- 涉及关键状态时，明确必须保持的约束（不变量）、适用的状态或确认边界，以及有权改变状态的主体和保证机制。多个主体可以协作；需检查协调或合并后约束是否仍成立，不能仅凭主体数量判错或凭存在合并规则判对。
- 涉及软件持久状态时，区分权威数据与派生数据，说明写入何时算成功，以及需要恢复的派生数据从何处重建。

## P03 最小充分性

- 判断：机制、选项、抽象和依赖都能解释其收益；同一规则有明确维护来源。
- 信号：同一业务规则多处独立修改；移除某机制后目标结果没有变化；为了统一而制造大量例外。
- 证据：删除或合并的影响分析、变更记录、实际消费者。不要删除有用途的备份与校验；两个表面相似的功能未必共享语义。更少代码不自动意味着更少复杂度。

## P04 职责清晰与耦合受控

- 判断：隔离易变化的决策，限制变化和故障的传播；紧密关联的工作有合适的归属。
- 信号：一个常见变化必须同步修改许多无关部分；循环依赖使启动或恢复无法进行。
- 证据：代表性变更路径、依赖关系、故障传播路径。分拆增加的网络、时序和协调成本也要计入。功能独立不要求物理零件分离。

## P05 明确接口与组合正确性

- 判断：数据/物料/能量的输入输出、单位、容差、顺序、超时、错误和版本边界明确。
- 信号：部件分别通过检查，集成却失败；消费者依赖未承诺的内部状态。
- 证据：契约与实际调用、装配约束、集成试验。不能仅靠接口存在就推断可互操作，也不要求把所有内部细节公开。
- 对可能阻塞、积压或部分失败的依赖，明确完成时限、可积压工作量和满载处置。软件调用若允许重试，还应明确各层责任、次数或时间预算及重复执行的效果；已有领域约束能保证上限时，不必另加控制机制。

## P06 可理解与可预测

- 判断：用户、操作人员和维护者能以适当成本形成准确模型，预测关键行为。
- 信号：相同操作在相似条件下无理由地表现不同；关键行为依赖隐含历史或个人记忆。
- 证据：典型任务走查、故障定位过程、命名与行为对照。明确“对谁可理解”；专家系统不必让所有人理解全部内部细节。

## P07 正确性可验证

- 判断：重要声明有能支持或推翻它的观察方法，要求、实现和证据对应。
- 信号：只测正常路径；只报告覆盖率；把原型效果当作生产容量或可靠性证明。
- 证据：与声明相关的分析、试验或观测，注明关键条件。验证“符合规格”与确认“满足实际需要”是不同问题；测试通过不代表无缺陷。

## P08 可观察与可干预

- 判断：关键异常能在有用的时间内被发现、区分，并采取有效行动。
- 信号：只知道失败却不能定位；告警很多但没人能处理；有停止按钮却无法安全停止。
- 证据：异常发现与定位场景、遥测、检查点、干预效果。并非每个部件都需要日志或实时遥控；监测的开销、隐私和新增故障点需计入。

## P09 鲁棒性与故障可控

- 判断：在预期扰动、参数误差、磨损和部分失败下维持必要功能或进入合适的降级/安全状态。
- 信号：轻微波动导致性能崩塌；备用与主系统共享同一单点故障；重试放大过载。
- 证据：容差/负载边界、故障注入、隔离和恢复场景。说明故障模型、冗余的独立程度与切换机制。安全行为由任务决定，停止并非永远最安全。
- 沿相关依赖路径检查：下游变慢、重复尝试或恢复时的集中处理，是否使需求超过处理和缓冲能力；既有降级与恢复措施能否保护必要功能。仅检查单个部件的故障响应不足以证明传播受控。

## P10 安全与权限边界

- 判断：误操作、攻击或越权造成的后果受限；权限与职责相称。
- 信号：普通任务依赖全局高权限；错误输入穿透边界；保护失效后默认允许危险动作。
- 证据：与当前操作相关的权限、危险路径和控制检查。信息安全与人身/设备安全需分别辨认；不要对普通低风险任务自动启动完整威胁建模或认证流程。

## P11 可演进与变化局部化

- 判断：预期功能与环境变化能以局部、可理解的代价完成，稳定承诺和允许变化的部分清楚。
- 信号：每次演进都破坏外部消费者；旧接口无人使用却长期阻挡修复；迁移只能一次性全量切换。
- 证据：代表性变化场景、消费者、兼容与迁移约束。不要冻结全部内部接口，也不要为尚无依据的未来变化付出确定成本。

## P12 容量与扩展边界

- 判断：目标负载下的响应、吞吐、能耗、占地或资源使用符合要求，知道瓶颈及扩容代价。
- 信号：只测试平均负载；共享资源或串行环节限制增长；扩容后协调成本反而更高。
- 证据：容量模型、代表性测量、极限及退化曲线。区分增加功能与增加负载；承认合理上限，有限规模系统也可以优秀。

## P13 可制造、可运营与可维护

- 判断：能够稳定制造/部署、诊断、修复和替换，必要人员、知识、工具及备件可获得。
- 信号：只有原作者能处理故障；简单故障需大范围拆卸；部署结果不可复现；无人维护关键依赖。
- 证据：一次代表性维修/部署/交接、装配公差或依赖清单。维修单元不一定越小越好，一体更换也可能更经济。

## P14 整体与全生命周期经济性

- 判断：建设、运行、维护、故障和退出成本与任务收益相称；没有把成本隐藏到边界外。
- 信号：提升一个零件的效率却降低整机产出；减少库存却使关键停工成本显著上升。
- 证据：相同任务下的资源与成本比较，注明估算条件和不确定性。不要只优化局部利用率；资料不足时用区间或定性判断，不伪造精确收益。

## P15 反馈与持续纠错

- 判断：异常和运行反馈能进入设计或流程调整，有负责处理的人或机制，并能确认效果。
- 信号：同类故障不断靠人工救火；复盘很多却不改变系统；局部指标激励整体不良行为。
- 证据：一条问题从发现、修正到效果确认的闭环。一次性系统可将经验传入后续任务；不要求所有系统自主学习，也不以增加审批代替修复机制。
- 设计与实现不一致时，先核对当前有效的要求和决定，区分实现缺陷、仍适用的已接受例外、需求变化、规则过时或原因待查，再决定修实现、修规则或补证据。这些解释偏差原因；发现的证据等级和性质仍按主流程判断。

## 冲突处理

| 冲突 | 应比较的实际量或场景 |
|---|---|
| 简洁 / 可靠 | 删除机制节省多少复杂度，会暴露哪类失败，现有控制是否足够 |
| 模块化 / 集成 | 变更与替换范围，对性能、重量、连接和制造的影响 |
| 兼容 / 演进 | 谁依赖旧行为，迁移成本与继续保留缺陷的代价 |
| 通用 / 专用 | 已知变化是否值得增加选项、状态、学习及验证成本 |
| 利用率 / 余量 | 真实波动和故障条件下的有效产出、等待、损失及恢复 |
| 可观察 / 成本与暴露 | 哪个判断或行动需要这些数据，采集是否引入过大开销或敏感信息 |

先确认硬约束，淘汰不可行方案；再在同一场景下比较取舍。不能通过平均分掩盖关键要求不满足，也不能仅凭“更先进”推荐方案。
