# 迁移设计方法

用于旧系统含义、消费者或过渡状态会改变迁移方案的情形，是 P11 的条件性展开。按当前问题选择下述部分，复用现有设计、任务及证据；不要求新增清单文件、治理角色或审批流程。

## 对照含义与消费者

以行为、契约、数据含义和消费者为单位比较旧系统与目标，而非按文件逐一搬迁。先界定本次范围，再追踪会影响处置的调用、读写、集成或实际使用路径；缺少说明时结合实现、运行观察和仍有效的历史决定补证。

为范围内的重要对象说明处置及依据：

- **保留**：目标继续承担的含义和约束，以及证明其保持的证据。
- **转换**：含义或表示有意改变，说明转换规则、损失及消费者如何适配。
- **替换**：由另一能力承担原职责，说明覆盖范围、接口变化及替代证据。
- **退役**：说明不再承担的职责、受影响消费者的处置和保留/恢复要求。

旧行为只是事实证据，不能自动成为正确标准；目标侧测试通过也不能单独证明旧职责已覆盖或可删除。以现行需求、已授权决定及真实消费者约束判断，区分旧缺陷与有效承诺。依据冲突时沿现行决策边界解决，不自行把观察升级为需求。

消费者、目标契约或历史含义尚未查明时，保留暂定处置与缺口，并说明下一步所需的最小证据；不能将未找到调用等同于不存在消费者。涉及职责或数据读写归属转移时，明确新旧边界及切换时机，避免两边都能作出互相冲突的决定。

## 设计过渡与收敛

存在分阶段切换时，比较可行的增量共存与一次性替换路径，依据约束选择；不把渐进迁移当作无条件要求。需要共存的方案至少说明：

1. **状态和切换**：支持哪些旧、混合及新状态，各状态必须保持什么约束；切换前置、观察信号和成功标准是什么。分别验证的多个对象不能据此声称整体原子切换。
2. **部分失败与恢复**：如何识别停在哪一步，区分已完成、失败和结局未知；如何修复、继续或停止。重复执行是否安全须有依据，未知结局先核对实际状态。
3. **恢复边界**：哪些数据、物料或外部效果不会随程序回退自动还原；不可逆点在哪里，如何备份、重建、旁路或控制损失。恢复方案需要与声明相称的验证，不能只写“可回滚”。
4. **兼容退出**：兼容层服务哪些消费者、由谁维护、何时可移除；用什么证据确认消费者迁移、旧入口停止使用及必要数据完成处置。没有退出依据时明确保留，不把目标上线等同于迁移收敛。

验证选择应覆盖会改变判断的旧职责、目标行为、混合状态及失败/恢复路径。对象、版本、环境或关键假设改变时，重新核对受影响证据；不默认穷举所有组合。

例如，订单金额从整数分改为十进制元，不能只证明新服务正确计算：还需识别旧消费者是否仍按“分”读取，说明双版本期间谁写入、如何区分单位，以及程序回退能否读取已经转换的数据。兼容读取器的移除取决于消费者和数据转换证据。

## 交给实施的最小结果

输出足以支持下一步的范围、处置依据、状态/切换条件、兼容责任与退出证据、恢复边界及未决事项。已经存在的任务和验收直接引用，不另建并行生命周期。已获授权的实施按主入口继续执行；授权未涵盖的含义改变或不可逆动作沿项目既有边界处理，不重复请求有效授权。

仅有设计或部分迁移证据时限定结论。未支持的不可逆步骤暂不推进，独立工作可继续；范围内处置与过渡条件足以指导当前动作时结束分析。新消费者、未覆盖的混合状态、恢复失败或失效证据出现后，仅重开受影响部分。
